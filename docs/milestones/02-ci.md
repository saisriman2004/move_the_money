# 2. CI pipeline and linting

**What.** A GitHub Actions workflow (`.github/workflows/ci.yml`) that runs on every push to `main` or `v2` and on pull requests: `npm ci`, lint, typecheck, migrate, test, build, against a real PostgreSQL 16 service container. ESLint with `typescript-eslint` (`npm run lint`).

**Why.** From here on, every milestone is checked automatically on a clean machine, not only on the laptop it was written on.

**How.** The workflow starts `postgres:16` as a service with a health check, sets `DATABASE_URL`, and runs the same scripts a developer runs locally. The test helper creates and migrates `move_money_test` itself.

**Decisions.**
- TypeScript is pinned to 6.0. `typescript-eslint` does not support TypeScript 7 yet (it requires `<6.1`), and type-aware linting needs it. The code typechecks unchanged on 6.0.
- ESLint found one real issue: the migration runner re-threw errors without keeping the original as `cause`. Fixed.

**What can fail.** The workflow could not be run on GitHub from this machine (no `gh` CLI, private repo). It was validated by running the identical steps on a clean copy of the repo against a `postgres:16` container with password authentication, which also exercised password-based connection URLs for the first time. All steps passed, 114 tests.
